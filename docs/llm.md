# Модель для резюме: подключение, выбор, дообучение

Демо и сервер публикации работают в `LLM_MODE=mock`: модалка пишет
фиксированный черновик, сеть к модели не вызывается. Этот файл — как
переключиться на настоящую модель и какую брать.

## Что делает модель, а что код

Числа оценки резюме и процент соответствия вакансии считает код. Модель нужна
для трёх вещей:

- черновик резюме по свободному тексту — `POST /api/v1/resumes/generate`;
- подгонка резюме под вакансию — `POST /api/v1/resumes/{id}/tailor`;
- переписывание текстов рекомендаций после оценки.

Если модель недоступна, generate и tailor отвечают 502, а оценка сохраняется
с шаблонными фразами. Логи не получают ни ключ, ни сырой текст биографии.

## Как адаптер зовёт модель

Бизнес-логика ходит только в `app/adapters/llm.py`. В real-режиме — один запрос:

`POST {LLM_BASE_URL}/chat/completions`

с `Authorization: Bearer …`, `temperature=0` и
`response_format: {"type": "json_object"}`. Ответ берётся из
`choices[0].message.content` и должен быть строкой JSON. Дальше схема
`ResumeDraft`. Невалидный ответ повторяется один раз (`LLM_MAX_RETRIES=1`),
затем 502 `LLM_RESPONSE_INVALID`. Таймаут — `LLM_TIMEOUT_SECONDS` (30).

Непустой `LLM_BASE_URL` важнее `LLM_PROVIDER`. У `openai` и `openrouter` URL
можно не задавать: подставятся `https://api.openai.com/v1` и
`https://openrouter.ai/api/v1`. У `anthropic` своего Messages API нет: без
`LLM_BASE_URL` вызов падает, с URL уходит тот же chat-completions.

Смена модели — это адрес, ключ и имя модели в `.env`. Веса в процесс API не
встраиваются. После правки `.env` — `docker compose restart api`.

## Подключение

### Своя модель (основной путь)

Поднимите OpenAI-совместимый сервер (Ollama, llama.cpp, vLLM) отдельно от
`docker compose up`. С ноутбука, API в Docker на Windows:

```
LLM_MODE=real
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_API_KEY=local
LLM_MODEL=qwen2.5:7b-instruct
LLM_TIMEOUT_SECONDS=120
```

Порт — тот, на котором слушает инференс (Ollama — 11434). Ключ — любая
непустая строка, если сервер его не проверяет. На CPU 7B часто не укладывается
в 30 секунд — поэтому таймаут поднят. Если сервер отвергает `response_format`,
поле надо сделать необязательным в `RealLLMAdapter`: сейчас оно отправляется
всегда.

Быстрая проверка без сайта: `scripts/check_local_llm.py`.

### Коммерческий API (запасной путь)

```
LLM_MODE=real
LLM_PROVIDER=openai
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
```

OpenRouter — `LLM_PROVIDER=openrouter` и его ключ. Роутер Hugging Face —
`LLM_BASE_URL=https://router.huggingface.co/v1` и токен HF. Inference
Endpoints — URL эндпоинта в `LLM_BASE_URL`. Во всех этих вариантах текст
биографии уходит провайдеру, а цена растёт с каждым черновиком, поэтому они
не основной путь.

### Проверка

В модалке «Сгенерировать через ИИ» ввести текст о себе. Ответ 201 и резюме с
`origin=generated` значит, что модель прошла схему. Если черновик каждый раз
один и тот же — режим всё ещё mock или контейнер не перезапущен.

## Где крутить модель

Сервер публикации (2 ядра, 4 ГБ, 40 ГБ) веса не вмещает: Qwen2.5-Instruct 7B
в Q4 — около 5 ГБ на диске и несколько гигабайт в памяти. Веса не кладутся на
этот сервер и не коммитятся в git.

| Где | Когда | Как стыкуется |
|---|---|---|
| Ноутбук с GPU, Ollama | Проверка промптов, редкие запросы. RTX 5070 тянет 7B | `host.docker.internal` из Docker на Windows |
| Отдельная машина с GPU | Сайт должен отвечать, когда ноутбук выключен | VPS знает приватный адрес как `LLM_BASE_URL` |
| Профиль Compose с vLLM | Постоянный стенд на Linux с NVIDIA | Не входит в обычный `up`; на Docker Desktop под Windows не рассчитывать |

Пока у сервера публикации нет сетевого доступа к машине с моделью, на нём
остаётся `LLM_MODE=mock`. Блок для `.env.prod` — в [deploy.md](deploy.md).

## Как выбрать модель

Своя модель с нуля не нужна — берём готовую инструкционную. Требования:
chat-модель (не базовая и не эмбеддинг), понимает русский, стабильно отдаёт
один JSON-объект по большой схеме `ResumeDraft`.

Метрика приёмки — доля ответов, прошедших `ResumeDraft`, на наборе из 30–50
своих биографий, плюс ручной просмотр нескольких черновиков. Не BLEU.

- Первый кандидат — Qwen2.5-Instruct 7B (`qwen2.5:7b-instruct`).
- Только CPU и 16 ГБ RAM — 3B.
- 7B часто не проходит схему — 14B (Q4 около 9 ГБ), а не смена провайдера.
- Слабый русский — Vikhr или Saiga на том же сервере, меняется только имя модели.

## Дообучение

Только если готовая модель на проверочном наборе часто не проходит схему или
путает секции. QLoRA поверх той же модели, не полное обучение.

- Датасет: пары «свободный текст о себе» → JSON `ResumeDraft`, несколько
  сотен пар: сид-резюме, размеченные вручную биографии, синтетика из удачных
  черновиков.
- Инструмент: Unsloth, Axolotl или TRL; адаптер на 7B–14B учится на одной GPU 24 ГБ.
- Проверка — тот же набор и та же метрика.
- Выкладка: влить LoRA в веса или отдать адаптер в vLLM. Для сервиса меняются
  только `LLM_MODEL` и адрес. В репозиторий — максимум скрипт подготовки
  датасета, не чекпоинт.
